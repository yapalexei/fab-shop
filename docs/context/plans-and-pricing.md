# Plans and pricing

Launch prices (hypotheses, not market-validated), seeded by `PlanSeeder` (after launch a platform admin owns them - see "Tier management" below; re-running the seeder only rewrites each tier's *current* version): Solo $29 (1 seat), Shop $59 (4 seats; the plan's key is still `start-up`, only its display name changed), Pro $119 (10 seats). Job board, quote history and AI quote drafting start at Shop; material tracking, qualification records and `Feature::AiAgent` (MCP access) are Pro, with the first two also sold as $25 add-ons. The default trial is 30 days (`PlatformSetting::DEFAULT_TRIAL_DAYS`); `Shop::TRIAL_DAYS` (14) remains only as the legacy baseline fallback. Extra seats: `plans.extra_seat_price_cents` ($9 on Shop and Pro, null on Solo = can't buy) and `shops.extra_seats`; `Shop::seatLimit()` = plan seats + extras (or the admin override), and `seatCapacity()` is what's enforced (trial shops get the top plan's seats). Enforced at invite (`SendShopInvitation`, pending invites hold a seat) and at accept; bought via `ShopSeatController` (owner-only, needs a live billing period, can't go below people already seated). Reducing seats is immediate, no refund. `PlanAdvisor` ignores seats.

## Tier management (platform admin: versions, expiry, history)

A platform admin adds, edits and retires tiers at Platform admin > Plan tiers (`PlanSettingController`, `PlatformAdmin/Plans.tsx`, `can:platform-admin` only - nothing here is reachable from a shop's pages). Tiers are **never edited in place or deleted**, because shops may still be on them:

- **A `plans` row is one *version* of a tier.** `key` names the tier and is shared by every version; `version` counts up; `superseded_at` is set on a version when a newer one replaces it. `(key, version)` is unique and a partial unique index allows exactly one current (not superseded) row per key. A shop's `plan_id` points at the exact version it signed up for, so `$shop->plan->monthly_price_cents`, `->user_limit`, `->features()` and `extra_seat_price_cents` keep returning what it bought - `Billing`, `seatLimit()`, `hasFeature()` and the revenue summary needed no change.
- **`Plan::applyEdit()`**: if the name, price, seats, extra-seat price or feature list changed (`Plan::VERSIONED` + features), it archives the current row and publishes a new version (copying `stripe_price_id`); otherwise it updates `position` / `expires_on` / `show_expiry` in place. Archived versions can't be edited (`PlanSettingController::ensureEditable()`). Nothing moves existing shops to a new version - that is deliberately not built (see below).
- **What is offered**: `Plan::scopeOffered()` = current version AND (`expires_on` null OR `expires_on` > today). **Everything that lets a person pick a plan goes through `Plan::orderedByTier()` / `Plan::offeredByKey()`** (marketing page, onboarding, the shop Plan page, `PlanAdvisor`, the trial seat cap). Never look a plan up by `where('key', ...)` for a *new* assignment - that can return an archived version; use `Plan::current()` / `offeredByKey()`. `expires_on` is the date the tier leaves the list (exclusive); `show_expiry` decides whether the marketing/onboarding/Plan pages print "Available until ..." (otherwise it just disappears). "Remove from public list" sets `expires_on` to today.
- **Order is the `position` column**, not the old hardcoded key list (`Plan::DEFAULT_ORDER` is now only the factory/seeder default). "Higher tier" comparisons (upgrade-only on the Plan page, `Shop::canUpgrade()`) use `Plan::rank()` - the tier's *current* position - so a shop on an archived version still compares correctly. Ties are not an upgrade.
- **The Free tier (`Plan::FALLBACK_KEY`)** is where a shop lands when its trial ends: editable (and versioned) like the others, but it can't be given an expiry or retired.
- **A shop on an archived version or a retired tier** keeps working and can switch its own plan to annual billing at its own price; the Plan page shows a notice (the `currentPlan` prop is the plan it is actually on, separate from the offered `plans` list) and it can only move to a *higher* tier. It cannot "move" to the newer version of its own tier - there is no migrate-subscribers action yet; add one (bulk `plan_id` update, with an `activity` entry and a confirmation of the price change) if grandfathering needs to end.
- **The page** (`PlatformAdmin/Plans.tsx`) draws each tier as a card like the landing page's (4-column CSS grid at `lg`), with a pencil (opens the edit dialog) and an archive icon (confirmation dialog, then `plans.retire`; hidden for Free), plus a dashed "+" tile that opens the same dialog empty. "Archive" = sets `expires_on` to today; clearing the date in the edit dialog brings it back.
- **History** (at the bottom of a tier's edit dialog): every archived version with its values, the dates it was in effect and how many shops are still on it (`shops.plan_id` count, trial and Free shops included). The shop directory's plan filter / override dropdown lists archived and removed versions that still have shops, labelled.
- Create/change/remove each write a `platform admin: plan tier ...` entry to the security log (no shop id - it's platform-wide).
