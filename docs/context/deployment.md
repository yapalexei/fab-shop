# Deployment (Railway)

Production runs on Railway from the root `Dockerfile` (one image, four services - web/horizon/scheduler/reverb - differing only in start command), with Postgres, Redis and an S3-compatible bucket. The whole project is Railway IaC in `.railway/railway.ts` (`railway config plan`/`apply`, run from CI on merge); app code deploys on push to `main`. Don't add `railway.json` files - IaC can't manage services that have them. Full setup and variable list: [docs/deploy-railway.md](../deploy-railway.md). Two things differ from Sail and matter when changing code: services don't share a filesystem, so anything written by one process and read by another (job photos, quote PDFs, CSV import uploads) must go through the default/media disk - never `Storage::disk('local')->path()` or `Media::getPath()` - and photo URLs go through `JobController::photoUrl()` (signed URL on S3). Reverb has separate browser (`REVERB_HOST`/`PORT`/`SCHEME`) and server-to-server (`REVERB_INTERNAL_*`) settings.
