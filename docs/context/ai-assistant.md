# AI assistant (bring-your-own-key)

`Feature::AiAssist` (`ai-assist`) is a Start-up-and-above feature (`PlanSeeder`, plus a migration for existing databases) - trial gets it via `Shop::hasFeature()`, so when a trial ends on Free it simply stops, with no separate expiry logic, and resumes the moment the shop is on Start-up. `isShipped()` is true now that quote intake exists - if every AI feature is ever switched off again, flip it back, or the marketing page overclaims.

Each shop brings its own provider key at `/shop/ai` (Owner-only, `manage-shop`, never delegable - it spends money and decides where customer text is sent). `ShopAiSetting` (`shop_ai_settings`, `BelongsToShop`) holds provider + model + the key; the key is an `encrypted` cast, `$hidden`, **write-only** (the page only ever gets `keyHint()`), and `api_key` is in `dontFlash` in `bootstrap/app.php` so a failed form can't flash it into the session. Provider and model come from the curated list in `config/ai.php`, never free text, and base URLs are fixed - no shop-supplied endpoint, so the key field can't become a request to an arbitrary host. Saving makes a real test call first (`AiManager::test()`); a rejected key is never stored. The OpenAI model names in `config/ai.php` are conservative placeholders - confirm them against OpenAI's current list before launch.

Code lives in `App\Services\Ai\`: `TextModel` (the main LLM; `AnthropicTextModel`/`OpenAiTextModel`, built on the `Http` facade like `QuickBooksClient` so tests use `Http::fake()`), `AiManager` (the one way to get a model - takes the `Shop` explicitly so queued work, which has no auth user, resolves the same as a request, and re-checks `hasFeature()` every call so a job queued before a trial ended stops when it ends), and `AiException` (messages are always safe to show - never the key or the provider's raw response). `DecisionModel` is an **unused interface**, the seam for a System 1 decision model (Jev/Clef/Tev1) as a later token-saving supplement to the main LLM - see the plan in `~/.claude/plans/`. `EnsureFeatureEnabled` lets *safe* requests through for any shop that ever trialed, so the AI settings page stays viewable (and says "paused") after a lapse while saving is refused; any AI endpoint or MCP route that must stop outright needs strict `hasFeature()`, not just the `feature:` middleware on a GET.

**Quote intake** (the first AI feature): the quote form's "Draft from a customer email" panel (`AiQuoteDraftPanel.tsx`) posts the pasted text to `QuoteAiDraftController` (`POST quotes/ai-draft`, strict `feature:ai-assist` + `quotes.create`; returns plain JSON, saves nothing). `App\Services\Ai\QuoteDrafter` sends the model only id + name (+ material type / what a tool cuts) for the shop's own catalog - never costs - with the customer's text fenced in `<customer_message>` and described to the model as untrusted data. The model only *chooses* (type, quantity, which catalog item); **cost and markup are filled client-side from the catalog** by `lineItemFromSuggestion()` (`resources/js/lib/aiQuoteDraft.ts`), mirroring what `QuoteLineItemCard` does when a person picks the item (cheapest supplier price, equipment rate, tool cost), so a model can never put a number on a quote. Every id it returns is checked against the list that was sent for that line type, and anything else (hallucinated, another shop's, wrong list) is dropped to "no match". Suggested lines are flagged with a client-only `ai_note` ("AI: check" badge) until the owner edits them. A message over `config('ai.max_message_length')` is rejected rather than truncated, and a catalog over `ai.max_catalog_items` per list tells the owner the draft only saw part of it.

`ai_requests` (`AiRequest`, `BelongsToShop`) logs every AI call - feature, provider, model, tokens, latency, ok/error - and deliberately **never the prompt or the answer** (customer data). It is written with an explicit `shop_id`, since the service can run without an auth user.

**Stale-quote follow-up**: a "Draft follow-up" link on each stale-quote row of the dashboard's attention list opens `FollowUpDraftDialog.tsx`, which posts to `QuoteFollowUpController` (`POST quotes/{quote}/ai-follow-up`, strict `feature:ai-assist` + `quotes.view`, sent and open quotes only). `QuoteFollowUpDrafter` drafts a subject and body; it **never sends** - the owner edits it, then copies it or opens it in their own mail app (`mailto:`). The model sees the shop, sender, customer name, send date, due date and what was quoted - **not** quote notes or customer notes (they can hold things never meant for the customer), not the customer's email, and the total only for someone with `financials.view`. Both AI features log through `AiUsage::record()`.

**Supplier-page intake**: the Add tool / Add material pages' "Fill from a supplier page" panel (`AiCatalogDraftPanel.tsx`) posts pasted product-page text to `CatalogAiDraftController` (`POST catalog/{tools|materials}/ai-draft`, strict `feature:ai-assist`, `tooling.create` / `materials.create` checked in `DraftCatalogItemWithAiRequest`; plain JSON, saves nothing, logs as `catalog-intake`). `CatalogItemDrafter` reads name, unit, part number and - for a tool - the listed price; **a price is the one number the model does supply here**, so a tool draft always comes back with a "check the price" note. Nothing is fetched (the owner pastes text, so no server request to an address they chose), the product link is typed by the owner and handed back untouched (the model never sees or writes one), and material types are chosen only from the shop's own list (any other id is dropped). A material draft has no price, part number or link: those live on the business partner's price row, not the material - so the **business partner form** has its own panel (`kind=supplier-prices`, needs `business-partners.create` or `.update`) that drafts one price row: the model may only pick the id of one of the shop's own materials (names and ids only are sent, capped at `ai.max_catalog_items`), an unmatched product adds nothing and points the owner to Materials first, and a matched one is added to (or refreshes) the price table client-side, saved with the form. The create pages and partner pages get an `ai` prop (`available`/`configured`) like the quote form.
