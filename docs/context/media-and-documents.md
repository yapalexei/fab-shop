# Pictures and documents

`App\Support\Images` is the one way a record gets a picture: a single Spatie-media file per record (`singleFile()` collection), JPG/PNG/GIF/WebP only (no SVG - it can carry script), 5 MB max, with a synchronous 256px square `Fit::Crop` conversion, so everything displays as a square (circle-masked for people and logos). User avatar (`avatar`), customer and business partner logo (`logo`), material photo (`image`). Files are streamed through the app (`users.avatar`, `customers.logo`, `business-partners.logo`, `materials.image`), never linked to the disk, so access follows tenancy and works on S3 - a user's avatar is only visible to themself and members of their current shop; the catalog images load for anyone who can see that resource *or* quotes/jobs (`EntityImageController`), since a logo shows wherever the name does. The URL carries `?v={media id}` so it can be cached hard. Forms post the file as `logo`/`image` plus a `remove_*` flag; updates are a POST spoofing PUT (`_method`) because PHP doesn't parse multipart PUT bodies. Lists must eager-load `media` before calling `avatarUrl()`/`logoUrl()`/`imageUrl()` or they N+1. Frontend: `Avatar.tsx` (`UserAvatar` initials fallback, `LogoAvatar` building icon, `SquareImage`) and `ImageField.tsx`.

Certifications can carry up to 3 documents (PDF or image, 30 MB each, `App\Support\CertificationDocuments`), uploaded live on a saved record (`certifications.documents.*`) or with the create form; the list shows a paperclip and count. Reuses `Attachments` for thumbnails and serving.
